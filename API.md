# Backend API

This document describes the HTTP routes implemented by `backend/index.js`.

## Base URL and formats

Use the deployed backend URL as the base URL (for example,
`https://your-service.onrender.com`). For local development, the default is
`http://localhost:3000`.

Requests with a JSON body must use `Content-Type: application/json`. Successful
JSON responses use `application/json`. No authentication is required by the
current routes.

## Data model

A user response has the following shape:

```json
{
  "id": 1,
  "name": "Ada Lovelace",
  "email": "ada@example.com",
  "created_at": "2026-10-14T08:00:00.000Z"
}
```

`id` is generated by the database, and `created_at` is set when the record is
created. `email` must be unique.

## Routes

### `GET /`

Health check. Runs a database query before reporting the service as healthy.

**Request:** No body or parameters.

**Response — `200 OK`:**

```json
{
  "status": "ok"
}
```

### `GET /users`

Returns all users, ordered by `id`.

**Request:** No body or parameters.

**Response — `200 OK`:** An array of user objects. An empty table returns `[]`.

```json
[
  {
    "id": 1,
    "name": "Ada Lovelace",
    "email": "ada@example.com",
    "created_at": "2026-10-14T08:00:00.000Z"
  }
]
```

### `GET /users/:id`

Returns one user.

**Path parameter:**

| Name | Description |
|------|-------------|
| `id` | The user's numeric database ID |

**Request:** No body.

**Response — `200 OK`:** A user object.

**Errors:**

| Status | Response |
|--------|----------|
| `400 Bad Request` | `{"error":"Invalid id"}` when `id` is not a valid database integer |
| `404 Not Found` | `{"error":"Not found"}` when no user has that ID |

### `POST /users`

Creates a user.

**Request body:**

```json
{
  "name": "Ada Lovelace",
  "email": "ada@example.com"
}
```

Both fields are required and must be non-empty. Additional fields are ignored.

**Response — `201 Created`:** The created user object, including its generated
`id` and `created_at`.

**Errors:**

| Status | Response |
|--------|----------|
| `400 Bad Request` | `{"error":"name and email required"}` if either required field is missing or empty |
| `409 Conflict` | `{"error":"Email already exists"}` if the email is already in use |

### `PUT /users/:id`

Replaces the user's `name` and `email`. Both fields are required; this route
does not support partial updates.

**Path parameter:** `id` is the user's numeric database ID.

**Request body:**

```json
{
  "name": "Ada Byron",
  "email": "ada.byron@example.com"
}
```

**Response — `200 OK`:** The updated user object.

**Errors:**

| Status | Response |
|--------|----------|
| `400 Bad Request` | `{"error":"name and email required"}` if either required field is missing or empty |
| `400 Bad Request` | `{"error":"Invalid id"}` when `id` is not a valid database integer |
| `404 Not Found` | `{"error":"Not found"}` when no user has that ID |
| `409 Conflict` | `{"error":"Email already exists"}` if the email is already used by another user |

### `DELETE /users/:id`

Deletes one user.

**Path parameter:** `id` is the user's numeric database ID.

**Request:** No body.

**Responses:**

| Status | Response |
|--------|----------|
| `204 No Content` | Empty response body when the user is deleted |
| `400 Bad Request` | `{"error":"Invalid id"}` when `id` is not a valid database integer |
| `404 Not Found` | `{"error":"Not found"}` when no user has that ID |

## Examples

Create a user:

```sh
curl -X POST "https://your-service.onrender.com/users" \
  -H "Content-Type: application/json" \
  -d '{"name":"Ada Lovelace","email":"ada@example.com"}'
```

List users:

```sh
curl "https://your-service.onrender.com/users"
```

Update a user:

```sh
curl -X PUT "https://your-service.onrender.com/users/1" \
  -H "Content-Type: application/json" \
  -d '{"name":"Ada Byron","email":"ada.byron@example.com"}'
```

Delete a user:

```sh
curl -i -X DELETE "https://your-service.onrender.com/users/1"
```

## CORS and preflight

The server allows `GET`, `POST`, `PUT`, `DELETE`, and `OPTIONS` for CORS. Browser
preflight `OPTIONS` requests are handled by the CORS middleware; there is no
separate application `OPTIONS` route. Requests without an `Origin` header are
accepted. Browser origins are allowed for localhost/127.0.0.1 on any port and
for exact origins listed in the comma-separated `ALLOWED_ORIGINS` environment
variable.

## General server errors

Unexpected errors return `500 Internal Server Error` with:

```json
{
  "error": "Server error"
}
```
